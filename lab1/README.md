# Лабораторная работа 1, вариант 5: Chroma key
## Теоретическая база
Цифровое изображение — двумерное изображение, представленное в цифровом виде.
Растровые изображения: прямоугольный двумерный массив чисел, при этом каждое число соответствует одному элементу изображения или пикселю.

Существует ряд цветовых пространств и моделей:
- CIE XYZ;
- CIE L*a*b;
- CIE RGB;
- RGB (аддитивная);
- CMYK (субтрактивная);
- HSV;
- HSL;
- YCbCr.

Модель HSV:
- Hue – цветовой тон, (например, красный, зелёный или сине-голубой). Варьируется в пределах 0—360°, иногда приводится к диапазону 0—100 или 0—1. В OpenCV от 0 до 180.
- Saturation – насыщенность. Варьируется в пределах 0 – 100 или 0 – 1. Иначе называется чистотой цвета. Чем меньше, чем ближе цвет к серому.
- Value (значение цвета) – яркость. Задаётся в пределах 0 – 100 или 0 – 1.
- Данная модель хорошо подходит для манипуляций с цветом (например, фильтрации по определенному цветовому тону), так как цвет определен одной координатой, поэтому и была выбрана для реализации Chroma key.

## Описание разработанной системы
Программа реализована на Python с использованием библиотек OpenCV и NumPy. Предусмотрены две реализации одного алгоритма:
- Библиотечная: построение маски с помощью cv2.inRange() и замена пикселей через cv2.copyTo().
- Собственная: последовательная проверка значений HSV каждого пикселя и копирование соответствующих значений средствами Python (через срезы).

Состоит из 4 функций:
- load_image() - загрузка изображения;
- chroma_key_opencv() - библиотечная реализация;
- chroma_key_native() - собственная реализация;
- main() - обработка аргументов, подготовка изображений, тестирование и сохранение результатов.

Поскольку основное и фоновое изображения могут иметь разные размеры и соотношения сторон, перед выполнением замен необходимо привести их к одинаковому разрешению. Для этого для второго изображения используется подход resize + crop, который предусматривает пропорциональное масштабирование фонового изображения с последующей обрезкой лишних областей по центру.

В собственной реализации изображения преобразуются в последовательности байтов с помощью .tobytes(). Обработка осуществляется в цикле с шагом 3, соответствующим трём цветовым каналам каждого пикселя. Для хранения результата используется bytearray, позволяющий изменять содержимое последовательности. После обработки результат преобразуется в массив NumPy.

Асимптотическая временная сложность обеих реализаций составляет O(W·H), поскольку каждый пиксель обрабатывается один раз. Общие операции загрузки, масштабирования и преобразования в HSV выполняются до измерения времени, поэтому сравнивается именно алгоритм проверки цветового диапазона и замены пикселей.

Пример запуска (для замены зелёного фона):
    py main.py imgs/f1.png imgs/b1.jpg 60 70 15 100 255 140

## Результаты
Полученные изображения для каждой из реализаций представлены в директории results.

Сравнение затрачиваемого времени:
    OpenCV: 0.012279 с
    Собственная реализация: 1.561994 с

 Ускорение OpenCV относительно собственной реализации более, чем в 100 раз. Это объясняется использованием скомпилированного кода и оптимизированных операций обработки массивов в OpenCV. В собственной реализации проверка условий и замена значений выполняются для каждого пикселя в цикле Python, что приводит к дополнительным накладным расходам интерпретатора.

## Выводы
Сравнение показало значительное преимущество библиотечной реализации по быстродействию, несмотря на одинаковую асимптотическую сложность алгоритмов.

Визуальное тестирование продемонстрировало зависимость качества работы алгоритма от выбранного цветового диапазона и характеристик исходного изображения. Наиболее заметные ошибки возникают при пересечении цветов объекта и заменяемой области, а также на границах объектов и участках с неоднородным освещением.
